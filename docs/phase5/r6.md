# R6: xlsx, pptx and pdf edit through the document server (owner decision 2026-11-08)

Owner: through the drop-in document server (`dropin.md`) xlsx, pptx and pdf are **editable too**, "only those that can be edited":
an edit session opens only when the backend's signed config allows editing (`mode=edit`, `permissions.edit`, a `callbackUrl`,
exactly as for docx) and only for a format our editor saves back without loss. This replaces `dropin.md` D5 (b) (view-only for
everything but docx) and PLAN 13.2 R6 ("after the gate").

## 1. Can each engine save its format faithfully? (measured 2026-11-08)

The round trip is open -> one edit -> save -> reopen with the engines' release CLIs built from this tree (`sheets-cli`,
`slides-cli`, `pdf-cli`: the same engine crates and writers the web editors run), then three independent reads of original
and saved file. Tools: `scripts/fidelity/r6/` (`gen.py` builds a feature workbook and deck, `resave.ps1` lets Excel and PowerPoint
re-save them and Word/Excel/PowerPoint export PDFs, `run.py` does the round trips, `compare.py` compares), plus
`scripts/fidelity/office_com.ps1 -Mode inspect` (Office 16's own structural counts) and `sheets-cli check`. Inputs: the repo
fixtures and shell templates, the Phase 0 synthetic HRM-shaped files (Office-made, on E: only), the generated feature files and
pdfcraft's signed and form fixtures. No corpus file (O9: `corpus/` is still missing).

| format | edit made | files | compared | lost content | other differences | verdict |
|---|---|---|---|---|---|---|
| xlsx | `cell.set` of an empty cell under the used range | 8 (3 Excel-made) | 1,917 cells (value/formula, number format, font, fill, borders, alignment, hyperlink, comment), merges, column widths/hidden, row heights/hidden, freeze panes, data validations, conditional formats, print area/orientation/paper, header/footer, sheet protection, tab colour, sheet state, images, tables, defined names, package parts (charts, drawings, media, comments, printerSettings) | **none** | 1 auto-fit row (no `customHeight`) 15.75 -> 16.5 pt (a cached height the writer recomputes); `calcChain.xml` dropped in 6 files (Excel's recalculation cache, rebuilt on open); 1 hidden built-in name `_xlnm._FilterDatabase` not written (its `autoFilter` is kept). Why pdf passes although "check pdf especially": pdfcraft never rewrites what it opened. `Session::save_bytes` appends the edited
objects (`pdfcraft-cos` "edits never touch the original bytes"); only three cases rewrite in full, each by design: a redaction
(it must remove content), a change of encryption, and a damaged file the user was told was repaired (#1937; not a signed one).
The web Save path (`save_view` -> `host_save`) uses `save_bytes`, the same function the CLI save measured here.

Not measured: files the engines open with warnings (legacy `.xls`/`.ppt`, which the docserver refuses anyway), pivot tables, macros
(`xlsm` is not an allowed `fileType`), embedded OLE objects other than chart data, SmartArt, animations and transitions, XFA forms,
real HRM files (corpus missing), and the browser save path itself beyond the CI fixtures (section 4).

## 2. What each bridge needs (the Docs bridge is the model)

| | Docs (wordcraft 0127/0128) | Sheets (gridcraft 0160) | Slides (deckcraft 0160) | PDF (pdfcraft 0122) |
|---|---|---|---|---|
| `open {readOnly}` honoured | Restrict Editing read-only; since wordcraft/0152 also the exceptions, Stop Protection and Undo are refused | refused before it runs or draws (section 5, gridcraft 0161/0162); the R6 take-back is only a logged safety net | same (section 5, deckcraft 0161/0162) | the document is view only in the engine (section 5, pdfcraft 0123/0124); File › Revert only as a logged safety net |
| `opened` | yes | **new** | yes (already) | **new** |
| `dirty` | yes | yes | yes | yes |
| `requestSave` -> `save` | yes | **new** (`requestSave`); Save/Save As send the .xlsx | yes; Save sends .pptx | **new** (`requestSave`); Save sends the PDF |
| `saved {ok}` ack, unsaved until acknowledged, `ok:false` marks unsaved | yes | **new** | **new** | **new** |
| `canDownload` / `canPrint` | greyed out + refused | exports refused (message), Print refused; exports otherwise download in the browser (before: sent to the host as a "save", which the server refused as a wrong package) | Export and Print refused through the command hook (greyed where the ribbon asks it), status message; exports and the print PDF download in the browser | Save As and every browser download refused ("Not allowed"); the Print dialog is closed |
| failed open/save | `failed` | `failed` | `failed` | `failed` |
| autosave every 30 s | yes | yes (gridcraft 0163) | yes (deckcraft 0162) | yes (pdfcraft 0124) |
| 50/100 MB caps | server (`max_document_mb`) | same server check | same | same |

The wrapper (`services/docserver/static/editor.js`) is unchanged except that it no longer counts a non-Docs document as open when
it is handed over: every bridge now answers `open` with `opened` or `failed`. The server needed no change: `editable()`,
the package check per `fileType` and the callbacks were already type-agnostic; the provider's `edit_types` default was already all
four. Only the installer and the image entrypoint narrowed it to docx; both now default to `docx,xlsx,pptx,pdf`
(`--edit-types docx` / `DOCSERVER_EDIT_TYPES=docx` keep the old behaviour).

## 5. Read-only blocked before it shows, and the 30 s autosave (owner 2026-11-08, branch `p5-ro`)

Owner: "a read-only session must not be changeable at all". The R6 bridges let an edit happen and took it back after the frame, so typed
text showed for one frame. Now every editor refuses the input or the command **before** it reaches the document, through the engine's own
read-only state or its command hook; the per-frame take-back stays in each bridge as a last-resort safety net that logs
`read-only safety net: ...` to the console, and every read-only test asserts it never fired.

| editor | mechanism | input paths refused before they change or draw anything |
|---|---|---|
| Docs | Restrict Editing read-only (0127) plus `protect::set_host_read_only` (0152): every command but the file commands is refused in `Session::run` before it runs | typing, paste, every editing command (0127); typing in an exception everyone may edit, Stop Protection, Undo/Redo (0152) |
| Sheets | `Session::read_only` (0161): `execute_inner` refuses every undoable command plus `edit.undo/redo/cut/beginEdit`, `draw.pen/eraser` before it runs, and `commands()` reports them disabled; a command that still dirtied a clean workbook is put back in the same call. UI (0162): `begin_edit` opens no cell editor, drags never start (`begin_drag`), header/footer and text box editors refuse; one toast, no modal per key | typing, F2, double-click, formula bar, Delete/Backspace, Ctrl+V/X/Z/Y, context-menu and ribbon commands, fill handle, move by border, row/column resize and move, chart/picture/shape move and resize, AutoFit |
| Slides | the R6 `HostPolicy` command hook (0162) refuses every undoable command plus undo/redo, the text composition commands and the open/new/revert commands; `Session::edit` (pointer gestures that edit with no command) and the drawing tools' press ask the same hook (0161); the notes pane, notes page and outline text fields are not interactive while locked; refusals show in the status bar | typing/Backspace/paste in a text, Ctrl+V/X/D, Delete, Ctrl+Z/Y, drag, resize and rotate handles, ribbon (New Slide, Bold), context menus, thumbnail reorder, image drop, notes pane |
| PDF | `Session::set_view_only` (0123): the document keeps its editor (rendering, forms, signatures, links) but `editable()` is false, so every `allows_*` check is false and the UI disables its tools with its own messages; `apply`, undo, redo, revert and unlock refuse with `ReadOnly`. The bridge sets it when the host's tab appears, before its first draw (0124) | Rotate via the command palette, sticky note, highlight, ink and shape drags, typing, Edit text and Add Text, Ctrl+X/V/Z/Y, Organize pages (buttons, context menu, thumbnail drag, Delete), form fields (type, check box, radio), Delete on an annotation, a file drop (opens another tab, this document unchanged) |

Known limits: in Slides the side-pane drafts for alt text, SmartArt lines and comment replies still take typed text into the field (the
command that would apply it is refused, nothing reaches the presentation); the Sheets comment/note editors, header/footer and text box
editors and the Slides outline view and drawing-tool preview are covered by code and engine tests, not by a browser case; PDF page
operations by menu, bookmarks, attachments, properties, security, redaction, OCR, headers/footers, flatten, Combine and links all end in
the refused `Session::apply` or a false `allows_*` check but were not each driven from a browser.

Autosave: each of the three bridges copies the Docs logic (wordcraft 0127, `AUTOSAVE_MS = 30_000`): while the document is dirty, the session
is not read-only and no save is waiting for its `saved` answer, every 30 s it posts `<prefix>:autosave {name, bytes}` (the .xlsx, .pptx or
PDF a save would send; nothing is marked saved, nothing downloads; a failed build logs and tries again next period; an idle page wakes with
`request_repaint_after`). The wrapper already forwards it to `POST /ds/session/{sid}/autosave` (a recovery copy: no version, no callback);
status 6 stays for explicit saves and the host's `requestSave` (PLAN 3.3). `editor.js` is unchanged. One difference from Docs: Docs does not
skip a period while a save is pending; the three new bridges do.
